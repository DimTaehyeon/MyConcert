# MyConcert

공식 버전 관리 기준: 기존 3차 QA 완료본(내부 표기 1.3.1)을 **1.0.0**, Git 태그 **1.0.0v**로 보관합니다. [버전 관리 기록](docs/VERSIONING.md)을 참고하세요.

**현재 버전 1.3.0:** 화면별 XML을 `app/src/main/res/layout`로 분리했습니다. Kotlin은 데이터 연결·사용자 동작을 처리하고, 공통 UI·라이트/다크 색상·배경·간격은 리소스로 관리합니다. 공연 상세의 저장 안내 아래 12dp 간격을 추가하고 아티스트명 일치 안내박스를 제거했습니다. [화면 파일 안내](docs/XML_LAYOUTS.md), [수정·검증 기록](docs/QA_1.3.0.md), 설치 파일 `output/MyConcert-1.3.0-debug.apk`.

저장소: [DimTaehyeon/MyConcert](https://github.com/DimTaehyeon/MyConcert) — **비공개**. 기존 Git 태그와 전체 변경 이력을 함께 관리합니다. [Figma](https://www.figma.com/design/D7NNqJrQzDyFViSuVjaCfX/MyConcert?node-id=2056-785)에는 기존 화면과 저장된 공연 상세 상태를 포함한 18개 화면이 있습니다. 이번 상세 변경도 편집 가능한 레이어로 반영했습니다.

선호 타일의 사진 배경·이름 캡슐과 메모리 전용 사진 표시는 유지합니다. [타일 화면](docs/PHOTO_TILES.md), [사진 조회 구현](docs/ARTIST_PHOTOS.md).

좋아하는 아티스트의 예정 공연과 이전 공연을 KOPIS에서 모아보는 Android 앱입니다. 제공된 Figma 시안의 흰 배경, 둥근 카드와 원본 로고·아이콘을 반영하고 아티스트 사진 타일을 추가했습니다. Kotlin과 XML 기반 Android Views를 사용합니다.

**1.1 QA 반영:** 지도 축척·위치 보정, 하트 버튼 개선, 현재 위치 기본 지역 선택, 광주·전남 통합 지역 코드 대응, 하단 제작 크레딧을 추가했습니다. [검증 내용과 실제 API 결과](docs/QA_2026-11-11.md)를 참고하세요. 현재 기능 테스트 32개와 빌드·Lint 검사(오류 0건)를 통과했습니다.

**1.2 / 2차 QA:** 조회 기준 표시, 미등록 아티스트 직접 검색과 검색명 저장·편집, 공연 더 보기의 새로고침 위치 수정, 맨 위로 이동 버튼을 추가했습니다. [기존 Figma 파일](https://www.figma.com/design/D7NNqJrQzDyFViSuVjaCfX/MyConcert?node-id=1-9)에도 14개 앱 화면을 반영했습니다. [2차 QA 기록](docs/QA2_2026-11-11.md)에 동작과 검증 범위를 정리했습니다. 현재 테스트 38개가 통과합니다.

**1.3.1 / 3차 QA:** 명확한 체크박스 선택과 반응형 선호 타일, 직접 추가한 아티스트 삭제를 반영했습니다. 추가 발견 후 승인받은 아이콘 설명 중복, 회전 시 선호 검색어 초기화, 저장 응답의 출처·시각 표시도 수정했습니다. Android 15·9에서 직접 실행했고 단위 테스트 40개가 통과합니다. [3차 QA 기록](docs/QA3_2026-11-11.md)과 [QA 관리표](docs/QA_ISSUES.md)를 참고하세요. 최신 설치 파일은 `output/MyConcert-1.3.1-debug.apk`입니다.

## 실행

1. Android Studio에서 이 문서가 있는 **MyConcert 폴더**를 엽니다.
2. 프로젝트 동기화가 완료되면 Android 7.0(API 24) 이상 기기를 선택하고 Run을 누릅니다.
3. 처음 실행하면 선호 아티스트를 최대 8팀 선택합니다. 선택하지 않고 시작한 뒤 추가할 수도 있습니다.

제공받은 API 키는 이 PC의 `local.properties`에 설정해 두었습니다. 이 파일은 버전 관리에서 제외됩니다. 다른 환경에서는 `kopis.api.key=발급받은키`를 추가하거나 `KOPIS_API_KEY` 환경 변수를 설정합니다. 키를 바꾸면 다시 빌드해야 합니다. 배포용 APK에도 키가 포함되므로 공개 서비스 운영 시에는 별도 서버에서 API를 중계하는 구성을 권장합니다.

개발 환경: 기존 프로젝트의 Android Gradle Plugin 9.3.3 / Gradle 9.5.0 / JDK 25 / compileSdk·targetSdk 37을 유지했습니다. Android Studio에 포함된 JDK를 사용하면 됩니다.

```powershell
./gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

설치 파일: `app/build/outputs/apk/debug/app-debug.apk`

## 기능

- 선호 아티스트 선택·편집·영구 저장, 한글·영문 아티스트 검색, 최근 검색 기록과 개별·전체 삭제
- 아티스트별 예정 공연·지난 공연, 기간 선택(30·90·180·365일), 선호 아티스트 홈 모아보기
- 전국 17개 지역 지도와 지역별 대중음악·복합 장르 공연
- 공연 상세, 출연진·일시·가격·관람 연령·포스터, API가 제공하는 예매처 링크, 공유, 캘린더 앱 연결
- 라이트·다크모드 저장, 화면 회전 시 진행 상태 유지, 이전 화면 복귀
- 로딩·중단·오류·재시도·부분 실패·빈 결과 구분, 저장된 응답을 활용한 오프라인 조회

## 아티스트 검색의 정확도

KOPIS `shprfnm`은 **공연명 부분 검색**입니다. 아티스트 전용 검색 조건은 없습니다. 예를 들어 `IVE`에는 `LIVE`가 포함된 수십 개 공연이 반환되었습니다. 원본 목록에는 출연진이 없으므로 후보마다 상세 API의 `prfcast`를 확인합니다.

1. 48팀의 한글·영문 공식 표기와 일부 투어명을 사전에 등록했습니다. 앱의 아이콘과 아티스트 카드는 이 검색 사전을 이용합니다.
2. 공연명에서 단어 경계를 확인하고, 영문 대소문자·띄어쓰기·표기 구분을 정규화합니다. `IVE`와 `LIVE`, `IU`와 `PREMIUM`을 구분합니다.
3. 그룹의 예명·실명은 출연진 검증에 이용합니다. 한 멤버의 이름만으로 그룹 출연을 확정하지 않습니다. 여러 별칭으로 적힌 같은 멤버도 한 명으로 계산합니다.
4. 멤버의 솔로·단독 팬미팅, 커버·헌정·실황 상영은 제외합니다. `JIN`과 `KWON JIN AH`, 그룹 `아이들`과 일반 명사 `아이들` 같은 모호한 표기는 추가 확인 없이는 확정하지 않습니다.
5. 투어명만 일치하거나 출연 여부가 불확실한 후보는 기본 결과에서 제외하고 건수를 안내합니다.
6. 기본 검색은 공식명·투어명이 있는 공연을 찾습니다. 아티스트 화면에서 **축제·공동 공연의 출연진까지 검색**을 켜면 대중음악·복합 장르 전체 후보의 출연진을 확인하므로 공연명에 아티스트가 없는 행사도 찾을 수 있습니다. 이 조회는 더 오래 걸리며 중단할 수 있습니다.

**검증 범위를 구분합니다.** 2025년 11월·2026년 8월·11월의 288개 검색 요청과 107개 상세 표본을 수집했습니다. 이 표본에 실제 매칭 규칙을 적용해 20팀의 검색어에서 일치 공연을 확인했습니다. 나머지는 사전 등록 상태이며, 표본에서 찾지 못했다는 이유로 공연이 없다고 단정하지 않습니다. 원본 조사에는 재시도 이전 HTTP 400 오류 23건이 포함되어 있습니다. 앱은 일시적 오류를 최대 2회 재시도합니다.

- 검색어 사전: `app/src/main/assets/artists.json`
- 확인 상태: `app/src/main/assets/verification.json`
- 원본 응답·조회 기간·오류: `docs/artist-verification.json`
- 구현 및 표본 재검증: `ArtistMatcherTest`, `ArtistSurveyTest`, `KopisXmlTest`

KOPIS에 미등록된 공연, 출연진이 누락된 축제, 검색 사전에 없는 표기는 누락될 수 있습니다. 기본 기간은 최근·향후 30일이며, 기간 밖 공연은 기간을 늘려 확인할 수 있습니다. 화면의 날짜는 한국 시간을 기준으로 합니다. Figma 시안에 있던 가상 공연은 실제 앱 데이터로 사용하지 않습니다.

## API와 저장

HTTPS API를 사용합니다. 조회 기간을 **각 요청 최대 31일**, 페이지당 **100건**으로 나누고 페이지를 순회하며 공연 ID로 중복을 제거합니다. 페이지 안전 한도에 도달하거나 일부 요청에 실패하면 화면에 부분 조회 안내를 표시합니다. 요청 사이에 간격을 두고, 화면 이동이나 새 조회 시 이전 작업을 취소합니다.

목록은 15분, 상세는 24시간 동안 저장된 응답을 재사용합니다. 연결에 실패하면 기존 응답을 표시하면서 저장된 정보임을 안내합니다. 새로고침은 캐시 유효기간과 무관하게 다시 요청합니다. 상세 검증을 할 수 없는 후보는 확정 결과로 표시하지 않습니다. 응답 캐시는 백업 대상에서 제외하고 선호 설정은 저장합니다.

## 검증

3차 QA에서는 Android 15와 Android 9 가상 기기에서 기기 테스트와 스크린샷 검사를 실행했습니다. 1.3.1의 단위 테스트 40개, 각 Android 버전의 기기 테스트 14개, 실제 KOPIS 조회·재방문 테스트 1개, APK 빌드와 Lint 검사(오류 0건)가 통과했습니다. 추가 발견 2개도 사용자 승인 후 수정하고 기존 실패 재현 테스트로 다시 확인했습니다. 실행 방법 및 로그는 [3차 QA 기록](docs/QA3_2026-11-11.md)에 있습니다.

```powershell
# 실제 KOPIS 표본 조사(네트워크·API 이용량 필요)
python tools/verify-artists.py
# 동일한 앱 매칭 규칙으로 표본 검증
./gradlew.bat :app:testDebugUnitTest
# 생성된 확인 상태를 앱에 반영
Copy-Item app/build/reports/verified-artists.json app/src/main/assets/verification.json
# 연결된 Android 기기에서 화면 흐름 검사
./gradlew.bat :app:connectedDebugAndroidTest
```

`AppFlowTest`는 선호 선택·한글/영문 검색·회전·다크모드·주요 화면을 검사하며, 화면 검증용 실제 API 표본은 `androidTest`에만 포함됩니다. 앱 실행 시에는 테스트 표본을 사용하지 않습니다.
